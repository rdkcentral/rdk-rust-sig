# Technical Proposals

Technical proposals in this directory are the default input for technical topics that require review and a decision by the RDK-B Rust SIG.

Proposals should also be used when requesting:

- a technical presentation for a SIG meeting, including its presenter, objective, intended audience, expected duration, and requested outcome
- creation of a task force, including its scope, owner, expected deliverables, and review date
- changes to SIG procedures or governance
- new engineering guidelines or updates to existing guidelines

Use [`TEMPLATE.md`](TEMPLATE.md) when creating a proposal. Submit the proposal early enough for participants to review it before the relevant SIG meeting.

## Review And Decision Process

1. Add the proposal to the SIG meeting agenda.
2. Use the proposal as the basis for technical discussion and decision-making.
3. Reference the proposal from the meeting record.
4. Record whether the proposal was approved, rejected, or deferred, including the main reasoning and any resulting action items.
5. Update the proposal status and add a reference to the meeting record containing the decision.

When a proposal is approved, apply the decision in the appropriate location. Create approved task-force records under `task-forces/`, update procedures or governance in the relevant repository document, and publish approved engineering guidance under `guidelines/`. These documents should reference the proposal and decision record where practical.

The meeting record is the authoritative source for a decision made during a SIG meeting. A proposal must not be described as approved or rejected unless that outcome is recorded there.
